## Hypothesis
The lr-only control for the learned_residual gains. e003 measured that the trained learned_residual 2x module is fixed pooling
plus a per-token MLP branch (latents 0.2% of the query, attention gate 1e-4, MLP gate 0.010), and attributed the e002 gain
over the pooled row to the compressor lr (1e-3 vs the pooled row's 2e-5), not to the learned queries. e004 then found the
gain growing with the ratio (4x: +2.3 MMBench, +2.0 DocVQA, +37 MME, loss -0.043 paired), and e006 the loss gap growing
again at 8x (-0.057). The pooled architecture has the same MLP branch and gates, so if the e003 attribution is right, `pooled`
queries trained at compressor lr 1e-3 reproduce the learned_residual 4x run (loss curve and gate scores) and the "learned
queries" rows of `tab:training-based` are a learning-rate result. 4x is chosen over 2x because the gain to reproduce is
largest there relative to item noise (at 2x the two rows are the same within noise, so the control could not separate them).
